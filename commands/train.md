argument-hint: [문서 종류] [import]

`bongvis/IDENTITY.md` 9절의 규칙을 따른다. 점수를 매기지 않는다 — 규칙의 변화만 기록한다.

## 기본 흐름

1. 어떤 문서(종류·경로)에 대한 피드백인지 확인한다.
2. 아래 다섯 지표 중 무엇이 발생했는지 묻는다. "좋았다/별로였다"는 받지 않는다.
   - 되물음 건수와 항목 (어떤 항목이 안 읽혔나)
   - 용어 지적 건수
   - 재작성 요청 여부
   - 문서 보고 작업하다 막힌 지점
   - 게시 후 수정 횟수
3. 피드백을 근거로 해당 `templates/<종류>.json` 의 어느 필드를 바꿀지 판단한다 (예: 새 `required` 섹션 추가, `ask` 문구 수정, `style` 보정).
4. 바꿀 규칙이 없으면(사소한 오탈자 등) `.bongvis/training.json` 에 기록하지 않는다 — 규칙이 안 바뀐 회차는 기록 대상이 아니다.
5. 바뀐 경우 `.bongvis/training.json` 의 `by_type.<종류>.rules[]` 에 항목을 추가한다: `learned`(날짜), `wrong`(무엇이 문제였나), `changed`(어느 템플릿의 어느 필드), `rule`(새 규칙 한 줄).
6. 실제로 `templates/<종류>.json` 파일을 함께 수정한다 — training.json 은 이력이고 템플릿이 집행자다. 이력만 쓰고 템플릿을 안 고치면 학습이 적용되지 않는다.
7. 읽은 사람이 없어 검증 못 한 피드백은 `unverified` 카운트에 넣고 템플릿은 건드리지 않는다.

## import (기존 문서에서 학습)

`$ARGUMENTS` 에 `import` 가 있으면: 기존에 쌓인 문서(Confluence 등)를 읽어 양식·용어·구조를 뽑아 템플릿과 용어집 개선안을 제시한다. 자기 채점 금지 원칙은 여기도 적용 — 기존 문서가 좋다고 스스로 판단하지 않고, 반복되는 패턴(같은 구조가 여러 문서에 나타남)만 근거로 삼는다.
