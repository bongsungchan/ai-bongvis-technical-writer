# Bongvis 작성·게시 실무 규칙

| | |
|---|---|
| 문서 번호 | BONGVIS-HS |
| 버전 | 1.0 |
| 상태 | **검증됨** — 이 규칙으로 쓴 문서 2건이 90점 통과 (2026-09-12) |
| 정본 | `bongvis/HOUSE-STYLE.md` (이 파일) |
| 상위 | [`bongvis/IDENTITY.md`](IDENTITY.md) — 정체성·원칙 |

`IDENTITY.md` 가 "무엇을 지키는가"라면 이 문서는 **"어떻게 쓰는가"**다. 아래 규칙은 전부 실사용 피드백에서 나왔고, 출처가 된 지적을 함께 적었다. 규칙마다 붙은 근거를 지우지 않는다 — 왜 그렇게 하는지 모르면 다음 사람이 되돌린다.

---

## 1. 문서 최상단 — 목적이 한눈에 보여야 한다

**최상단 3단 구성을 고정한다.** 순서를 바꾸지 않는다.

```
① 제목
② 목적 한 줄 — "이 문서는 무엇을 하는 문서인가"
③ 결론 콜아웃 — 결정문이면 결론, 설명서면 한 줄 요약
④ 메타표 — 결정 상태 / 읽는 사람 / 근거의 성격 / 작성일
⑤ 목차
```

> 📌 **목차는 결론보다 뒤에 둔다.** 목차가 먼저 나오면 스크롤해야 결론이 보인다.
> 근거 — "전체적인 내용은 좋으나 이것이 무엇을 위한 문서인지 한번에 보이지가 않음" (2026-09-12)

**목적 한 줄에는 다루지 않는 것도 적는다.** 범위를 문장으로 못박아 두면 이탈을 스스로 막는다.
예: "두 UI 작성 방식의 차이를 설명하는 문서다. 어느 쪽을 쓸지 정하는 문서가 아니다."

---

## 2. 범위 — 요구하지 않은 내용을 넣지 않는다

**가장 크게 감점된 항목이다.** 문서 종류가 정한 범위를 벗어나면 내용이 아무리 정확해도 깎인다.

| 문서가 다루는 것 | 넘어가면 안 되는 선 |
|---|---|
| 플랫폼 비교 | 그 플랫폼 위에서 **서비스를 어떻게 만들지**는 다른 문서다 |
| 개념 설명 | 어느 쪽을 **쓸지 권고**하면 결정문이 된다 |
| 결정 기록 | 결정과 무관한 **배경 지식 나열**은 부록으로 빼거나 뺀다 |

> 🔴 **실패 사례 (2026-09-12)** — 플랫폼 비교 문서에 로컬 DB 라이브러리 비교(Room/WatermelonDB/Drift/Isar), 오프라인 동기화 시퀀스, 사진 업로드 큐가 들어갔다. 지적: "우리는 단순 플랫폼 비교지, 서비스 개발 비교를 하는 것이 아님. 요구하지 않은 내용이 들어가 있음."

**작성 전 자문** — 이 절을 빼면 독자가 결정을 못 내리는가? 아니라면 부록으로 내리거나 삭제한다.

---

## 3. 강조 체계 — 중요한 것과 아닌 것이 구분돼야 한다

강조가 없으면 독자가 무엇을 봐야 할지 모른다. **아래 기호를 고정해서 쓴다.**

**판정 (결정문 전용)**

| 기호 | 뜻 |
|---|---|
| ✅ | 채택 · 충족 · 가능 |
| ❌ | 탈락 · 미충족 · 불가 |
| ⚠️ | 조건부 · 주의 |
| ⬜ | 미정 · 보류 |

**무게 (위험·영향도)**

| 기호 | 뜻 |
|---|---|
| 🔴 | 큼 · 심각 |
| 🟡 | 중간 |
| 🟢 | 낮음 · 영향 없음 |

> ⚠️ **설명서에는 판정 기호를 쓰지 않는다.** ✅/❌ 를 쓰는 순간 "어느 쪽이 정답"으로 읽힌다. 판정하지 않는 문서에서는 ①② 같은 중립 기호로 대비한다.

**콜아웃 4종** — 선두 이모지로 종류를 구분하고, 렌더러가 색을 입힌다.

| 선두 | 용도 | HTML | Confluence 매크로 |
|---|---|---|---|
| ✅ | 결론 | 초록 | `tip` |
| ⚠️ | 주의 | 노랑 | `note` |
| 🔴 | 경고 · 오해 | 빨강 | `warning` |
| 📌 | 참고 · 핵심 | 파랑 | `info` |

**각 절은 한 줄 요약으로 시작하고 그 줄만 볼드 처리한다.** 본문 전체를 볼드하면 강조가 사라진다.

## 4. 다이어그램 — 장식이 아니라 논거일 때만

`IDENTITY.md` 7-3 의 "언제 그리나"를 따르되, 아래를 추가로 지킨다.

### 4-1. 렌더 폭에 맞는 비율로 만든다

Confluence 는 이미지를 **900px 폭**으로 표시한다. 비율이 극단적이면 읽을 수 없다.

| 비율 (가로÷세로) | 판정 |
|---|---|
| 0.5 미만 | ❌ 너무 길다 — 스크롤해야 읽힌다 |
| **0.8 ~ 3.0** | ✅ 적정 |
| 3.0 초과 | ⚠️ 납작함 — 내용이 적을 때만 허용 |

렌더 직후 **반드시 픽셀 크기를 재고 비율을 확인한다.**

```bash
python3 -c "
import struct,glob
for f in sorted(glob.glob('*.png')):
    d=open(f,'rb').read(); w,h=struct.unpack('>II',d[16:24])
    print(f'{f} {w}x{h} 비율 {w/h:.2f} → 900px 환산 {round(900*h/w)}px')"
```

> 🔴 **실패 사례** — 판단 흐름을 세로(TD)로 그렸더니 1608×4899(비율 0.33)가 나왔고, 900px 폭에서 2742px 높이로 늘어져 한 화면에 안 들어왔다. 가로(LR)로 바꿔 해결.

### 4-2. subgraph 배치를 통제한다

- Mermaid 는 **subgraph 를 정의 역순으로 배치**한다. 왼쪽·위에 둘 것을 **마지막에** 정의한다.
- 연결이 없는 subgraph 는 **나란히(가로) 배치**되어 납작해진다. 세로로 쌓으려면 보이지 않는 연결 `A ~~~ B` 를 넣는다.

### 4-3. 아이콘을 쓴다

노드 라벨에 이모지를 붙이면 종류가 한눈에 구분된다. 고정 사용:
🎨 UI · 🗄️ 저장소 · ⚙️ 스케줄러·처리 · ☁️ 서버 · 📱 OS·기기 · 🔄 상태변경 · 🖥️ 화면 · 📝 기술·문서 · 🔍 탐색

### 4-4. 렌더 결과를 눈으로 본다

**그린 다음 반드시 이미지를 열어 확인한다.** 문법이 맞아도 의미가 뒤집힐 수 있다.

> 🔴 **실패 사례** — "명령형이 복잡하다"를 보이려는 그림에서, 선언형 쪽이 5행으로 늘어나 **오히려 더 복잡해 보였다.** 메시지가 정반대로 전달될 뻔했다. 재설계로 해결.

## 5. 출처 — 하이퍼링크로, 검증한 것만

- 본문에는 **번호 각주** `[1]` 를 쓰고, 하단 출처 목록에서 링크한다. 본문에 URL 을 노출하지 않는다.
- 출처는 **반드시 클릭 가능한 하이퍼링크**여야 한다.
- **인용 전에 URL 을 실제로 열어 확인한다.** 페이지 내용이 압축·부분 전달된 경우 **직접 인용하지 말고 요약·참조만** 한다.
- 수치가 자료마다 엇갈리면 **인용하지 않는다.** 엇갈린다는 사실과 이유를 적는다.

> 🔴 **실패 사례** — `md2conf.py` 가 마크다운 링크를 변환하지 못해 본문에 `([thedroidsonroids.com](https://...))` 가 날것으로 박혔다. 가독성 붕괴의 주원인이었다. → `scripts/md2storage.py` 로 해결.

## 6. 산출물 — `.md` 로 넘기지 않는다

> 📌 **근거** — "Local 산출물이 .md 면 읽을 수 있겠음? pdf 혹은 html 로 산출물 작성해" (2026-09-12)

- 로컬 산출물은 **HTML** 로 만든다. 다이어그램 SVG 를 인라인해 **외부 의존 없는 단일 파일**로.
- 마크다운은 사람이 읽는 산출물이 아니라 **변환 소스**로만 취급한다.

## 7. 게시 전 검증 — 4단 게이트

순서를 건너뛰지 않는다.

| 단계 | 무엇을 | 어떻게 |
|---|---|---|
| 1 | 다이어그램 비율 | 픽셀 크기 측정 (4-1) |
| 2 | 다이어그램 의미 | 이미지를 열어 눈으로 확인 (4-4) |
| 3 | HTML 렌더 | 헤드리스 브라우저 스크린샷으로 실제 화면 확인 |
| 4 | storage XHTML | 게시 전 XML 파싱 검증 |

```bash
# 4단계 — 깨진 마크업이 올라가지 않게
python3 -c "
import xml.etree.ElementTree as ET
d=open('storage.xml').read()
ET.fromstring('<root xmlns:ac=\"h\" xmlns:ri=\"h\">'+d+'</root>')
print('XHTML 파싱 OK')"
```

> 🔴 **3단계가 잡아낸 것들** — 이스케이프돼 날것으로 출력된 `<br>`·`&nbsp;`, 목적문 앞에 끼어든 목차, 메타표의 빈 헤더 띠. **전부 코드 검사로는 안 보이고 스크린샷으로만 보였다.**

**Confluence storage 주의** — `&nbsp;` 는 XML 미정의 엔티티다. `&#160;` 를 쓴다.

## 8. 도구

`scripts/` 에 있다. 재발명하지 않는다.

| 도구 | 역할 |
|---|---|
| [`scripts/build_html.py`](../scripts/build_html.py) | 마크다운 → 단일 HTML (SVG 인라인·목차·각주 앵커·콜아웃 색) |
| [`scripts/md2storage.py`](../scripts/md2storage.py) | 마크다운 → Confluence storage XHTML (**하이퍼링크**·콜아웃 매크로) |
| [`scripts/mermaid-theme.json`](../scripts/mermaid-theme.json) | 다이어그램 공통 테마 (한글 폰트·색) |

```bash
# 다이어그램
mmdc -i d.mmd -o d.png -c scripts/mermaid-theme.json -b white -s 3 -q
mmdc -i d.mmd -o d.svg -c scripts/mermaid-theme.json -b white -q

# 산출물
python3 scripts/build_html.py 문서.md 문서.html <다이어그램폴더>
python3 scripts/md2storage.py 문서.md storage.xml
```

**게시는 프로젝트의 기존 스크립트를 그대로 쓴다** (`IDENTITY.md` 3-3). 게시 로직을 새로 만들지 않고, 스크립트의 안전장치(`--confirm-outside` 류)를 우회하지 않는다.
