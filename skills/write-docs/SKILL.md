# Write Docs

코드를 읽고 그 코드가 **실제로 하는 일**만 문서로 옮긴다. 추측한 동작은 쓰지 않는다.

## 절차

1. **대상 확정** — 문서화할 범위(파일/모듈/기능)와 독자(최종 사용자 / 기여자 / API 소비자)를 확인한다. 불명확하면 묻는다.
2. **근거 수집** — 진입점, 공개 API 시그니처, 설정값, 에러 케이스를 코드에서 직접 읽는다. 기존 문서는 참고만 하고 사실 확인은 코드로 한다.
3. **작성** — 아래 구조를 기본으로 하되, 대상에 맞지 않는 절은 넣지 않는다.
   - 한 줄 요약 (무엇을 왜)
   - 설치 / 준비물
   - 최소 실행 예제 (복사해서 바로 돌아가는 것)
   - 주요 API·옵션 표
   - 흔한 실패와 대처
4. **검증** — 문서에 넣은 명령어와 코드 예제는 실제로 실행해 확인한다. 확인 못 한 예제는 그렇다고 명시한다.

## 원칙

- 코드에서 확인되지 않은 동작·성능 수치·지원 범위는 쓰지 않는다.
- 예제는 축약하지 말고 그대로 실행 가능한 형태로 둔다.
- 기존 문서의 톤·용어·구조를 따른다. 새 스타일을 도입하지 않는다.
- 변경한 문서는 무엇을 왜 바꿨는지 한 줄로 보고한다.
